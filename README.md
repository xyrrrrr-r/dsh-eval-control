# dsh-eval-control

DSH 轨迹分析与 aeval 评测控制插件。

在会话中查看上下文如何增长、哪些消息消耗 Token、压缩替换了什么，以及工具和 Team 的运行情况；对比不同会话，下载差异报告，或生成带有效期与密码的只读分享链接。

同时提供 aeval 所需的变量注入、预算控制、fork 血统校验和证据描述文件。普通轨迹分析与评测控制独立工作：查看面板不需要配置评测试次。

本文对应仓库当前实现，`package.json` 版本为 `0.3.0`。发行包的功能取决于实际安装版本。

## 快速开始

### 安装发行包

先准备可用的 DSH 宿主，再向目标 profile 安装插件：

```bash
dsh plugin --profile web add dsh-eval-control
```

将 `web` 替换为实际使用的 profile。需要固定发行版本时，在包名后追加 `@<version>`。

重启或重新加载该 profile，打开一个会话，在会话顶部选择 **轨迹分析**。对话区的 `aeval 控制` 状态胶囊和侧栏插件详情提供评测控制状态。

### 使用当前源码

在仓库根目录执行：

```bash
npm install
npm run build
npm run typecheck
```

将构建后的本地目录安装到目标 profile：

```bash
dsh plugin --profile web add /absolute/path/to/dsh-eval-control
```

随后重新加载该 profile。`client/client.js` 是生成产物，前端修改应编辑 `client-src/`，再运行 `npm run build:client`。

### 环境要求

| 项目 | 要求 |
| --- | --- |
| Node.js | `^22.19.0` 或 `>=24.0.0` |
| 完整功能验证环境 | DSH `0.2.0-rc.2` 的 Web 界面 |
| 宿主依赖 | 满足 `package.json` 中全部 `peerDependencies`；部分服务要求精确的 `0.2.0-rc.2` |
| 轨迹分析 | 宿主会话及 projection 服务 |
| 诊断配置应用 | 宿主持久化配置编辑器 `configEditor` |
| 分享链接 | 宿主 HTTP 服务及本地 profile 存储 |

版本不满足时，宿主可能跳过整个组合包。可在插件页和宿主日志中检查 `incompatible-version` 等信息。

| Tab | 可以查看或执行的操作 |
| --- | --- |
| 总览 | 上下文窗口占用、组成拆解、会话摘要；右侧集中展示智能告警、规则设置和可折叠诊断数据 |
| 上下文演化 | 按步骤、轮次或时间查看输入占用、表面 Token 和输出 Token；区分摘要压缩、历史修剪、注入与激增 |
| 消息 Token | 消息级 Token 台账、类型和范围筛选、排序、高消耗与异常消息定位 |
| 压缩与注入 | 事件聚合、压缩前后对比、替换关系、替换手段、注入来源和内容节选 |
| 工具分布 | 调用次数、显式错误、工具分布图及调用明细 |

### 证据链：从结论回到原始事件

点击顶部指标卡、告警中的 **查看证据链**，或消息表中的 ⚡ / 🔻，会在右侧打开统一证据抽屉。演化图选中标记后可查看证据，也可使用 **请求证据** 选择请求；压缩、注入、工具明细、Team 成员与对比指标均有对应入口。总览右侧 **诊断数据 → 指标明细** 可查看各契约指标的事件引用。

抽屉显示结论、规则、实际计算输入、样本与分母、证据等级和数据质量提示。突增同时展示前 5 条已保留消息的基线中位数、相邻消息体积差、主导成分、服务商输出用量和时间间隔；这些数值分别标明来源，不将消息估算等同于模型输出，也不将时间相邻当成因果关系。

点击关联事件，按 `sessionId + seq` 读取宿主原始持久事件，高亮目标行、展示前后最多 3 条事件，并可查看 JSON 或下载本条记录。关联引用支持搜索和分页，跨会话引用保留所属会话。工具事件还可使用宿主的 **Trajectory 定位工具调用**。

当前宿主尚不支持任意序号在原生 Trajectory 中定位，因此普通事件在抽屉内的 **原始轨迹** 区查看。引用和投影均有保留上限；缺失、读取失败、未知分母或未记录的耗时起止会明确提示，不会用相邻事件代替。关闭抽屉保留原 Tab 的筛选和缩放。

![异常结论、检测依据与原始轨迹定位（演示数据）](docs/demo/panels/evidence-chain.gif)

实现和数据约定见 [证据链设计](docs/evidence-chain.md)。

### 上下文演化与缩放

演化图保留轮次内的请求样本，事件依据发生顺序定位。事件标记分行显示，摘要压缩和历史修剪独立计数、独立筛选；注入和激增按钮也展示数量。悬停查看详情，点击可固定事件；密集标记使用聚合气泡展示。

上下文演化与对比折线使用相同的缩放交互：

- 拖拽框选放大指定范围。
- `Shift` + 拖拽平移。
- 双击或点击 **重置缩放** 恢复横轴范围。
- 点击图例显示或隐藏曲线，保留当前缩放范围。
- 切换纵轴 **完整窗口 / 适配数据**。

滚轮正常滚动页面，不触发图表缩放。

### 压缩、修剪与注入详情

压缩详情把受影响的旧消息与替换后的内容分组关联，提供前后 Token、回收量、内容节选及替换手段。保留消息可按需显示；前后两列支持比例同步滚动。

摘要压缩展示模型生成 checkpoint 后进行范围替换的关系。历史修剪根据事件证据标注；无法确认的手段不会当作已证实的实现。

连续且满足时间与 Token 连续性条件的历史修剪会聚合为一个条目。同一显示秒内的注入事件也会聚合，展开后保留各原始事件的顺序与来源。

历史快照和节选有容量上限。需要完整事件记录时，可从总览右侧 **诊断数据** 使用宿主日志导出入口。

## 智能告警与配置应用

告警与诊断集中在 **总览右侧的诊断中心**，提供未处理、已处理、已忽略及严重级别筛选。告警详情包含检测时间、指标值、阈值、建议和相关图表或指标入口。

| 告警 | 默认触发条件 |
| --- | --- |
| 上下文满载 | 窗口占用超过 80% |
| 频繁压缩 | 摘要压缩超过 5 次 / 千输入 Token |
| 高错误率 | 工具显式错误率超过 10% |
| Token 浪费 | 同一参数调用最长连续重复超过 3 次 |
| 长间隔 | 存在至少一个 ≥30 秒的长间隔段 |

在 **规则设置** 中修改阈值或启停规则。规则保存在当前浏览器；忽略和处理状态按会话保存。修改告警阈值不会改变宿主运行策略。

上下文满载、频繁压缩告警支持两种配置操作：

1. **查看并调整配置**：读取真实配置文件路径、选择目标、查看当前值并调整推荐值，再点击应用。
2. **直接应用推荐配置**：读取并应用推荐策略；存在多个目标时需先选择。

可编辑的策略包括开启自动压缩与调整触发比例，并同步该目标中的模型覆盖策略。写入通过宿主配置编辑器完成，包含并发变更检查、配置校验、正常加载流程及回读确认；失败会显示原因。应用成功不会自动把告警标为已处理。

**预设中的配置修改对新建会话生效，现有会话保留原预设版本。** 界面会显示目标配置的生效范围。

工具错误、重复调用和延迟建议提供配置文件路径与手动处理指引；这些聚合指标不足以自动确定可靠的工具参数修复或缓存策略。

## 会话对比与差异报告

1. 打开 **对比分析**，搜索并勾选 2–4 个会话。当前会话可取消选择。
2. 点击 **开始对比**，读取所选会话的历史投影。
3. 查看 Token 条形对比、上下文演化折线和多维雷达图。
4. 点击指标高亮其差异，展开 **最佳实践** 查看检查建议。

系统默认高亮相对差异最大的一项。差异报告给出 Token 消耗、摘要压缩频率、工具错误率和模型耗时的最低值，支持并列，并显示可比数据覆盖数量。缺失数据标为不可用，不按零参与排名。

勾选 **归一化显示** 后，上下文曲线按窗口占用率与请求进度对齐。请求进度相同仅表示运行内的位置相近，不能据此认为任务阶段相同。

雷达图使用资源消耗比例：

```text
本轴半径比例 = 当前会话原始值 / 所选会话该项最大值
```

中心为 0%，外圈为 100%；全零轴均位于中心。越靠近中心，该项数值越小。图中提供轴上限、顶点详情和原始值表；雷达面积不代表任务能力或完成质量。至少三个指标在所有所选会话中均可用时才绘图。

对比结果是点击开始时的快照。改变选择后，需重新点击 **开始对比** 更新结果。

### 下载差异报告

完成对比后，点击顶部 **导出**，将模板设为 **团队版：多会话对比 + 建议**，选择 PDF、Markdown 或 HTML，再点击 **生成并下载**。

团队报告使用最后一次完成的对比快照；缺少对比数据时，界面会提示先完成会话对比。

| PNG | 当前 Tab 的首个可用 SVG 图表；无图表时提示切换视图 |
| HTML | 包含图表与文本的离线只读报告，无外部资源依赖 |

| 模板 | 内容 |
| --- | --- |
| 简洁版 | 关键指标与图表 |
| 详细版 | 当前可用投影的指标明细、事件、图表和告警分析 |

## 只读分享

点击顶部 **分享**，选择报告模板和标题，再设置：

- 有效期：7 天、30 天或永久。
- 访问权限：公开链接，或使用 8–128 字符的密码保护。

点击 **生成分享链接并复制** 后，可打开只读视图、再次复制或撤销刚生成的分享。密码错误时不返回报告；过期链接显示“链接已过期”。

分享快照保存在当前宿主 profile 的 `trajectory-shares/` 目录。宿主停止期间链接不可用，重启同一 profile 后可继续访问。`127.0.0.1` / `localhost` 链接仅本机可用；团队访问需从已有可达地址的宿主页面生成链接。

分享报告不包含原始消息正文、工具参数或替换内容节选。接收者打开的是隔离的只读快照，不能操作原会话。公开链接由持有链接者访问；密码保护的链接还需提供密码。

当前最多保留 100 份分享，每份 HTML 不超过 2 MB。创建后续分享时会清理过期超过一天的快照。密码以随机 salt + scrypt 存储，分享标识与宿主登录 token 分离。

## 数据口径与隐私

| 数据 | 口径 |
| --- | --- |
| 顶部及对比中的 Token 消耗 | 未缓存输入 + 输出，不等于计费金额 |
| 上下文窗口占用 | 请求输入占用，包含缓存读 |
| 表面 Token、消息组成与节选 Token | 启发式估算，与 `dsh-token-meter` 的镜像算法一致，`CHARS_PER_TOKEN = 4` |
| 压缩频率 | 摘要压缩次数 / 千输入 Token；历史修剪单独统计 |
| 工具错误率 | 已观察到的显式工具错误 / 工具调用数 |
| 雷达及最低值排名 | 所选会话内的资源表现；比较时应同时考虑任务规模、模型与完成质量 |

分析基于宿主提交的会话事件和投影。缓存与历史记录有上限，无法获取的内容会显示缺失状态。历史会话读取借用宿主只读会话引用，不启动 Agent。

本插件的分析与分享数据保存在本地。内容节选、复制、JSON 和完整日志导出可能包含原会话中已保留的路径或正文，分享前应核对所选导出内容。诊断中的配置应用由用户显式触发；该操作会持久化修改对应宿主配置。

## aeval 评测控制

评测控制用于把试次配置与实际运行绑定，包含实验变量、步骤与 Token 预算、fork 血统和 bundle descriptor；编排、评分与评测报告由 aeval 完成。面板导出的分析报告与 aeval 的正式判分报告用途不同。

默认组合包挂载两行：

| 行 ID | 职责 |
| --- | --- |
| `aeval-broker-transport` | 可选评测 transport；缺少控制配置时以 standalone 状态运行，不重定向模型调用 |
| `dsh-trajectory-analytics` | 注册轨迹分析投影、诊断配置和报告分享服务 |

`standalone` 表示评测控制尚未接入，不影响普通轨迹分析。完整评测控制还需要 `aeval-eval-control` 行，且 transport 必须排在控制行之前。

配置来源支持完整内联配置、`controlConfigPath` 指向的 JSON 文件，或空行配置配合 `AEVAL_CONTROL_CONFIG` 环境变量。以下为完整控制栈的行配置示意，JSON 文件应由评测运行方提供：

```yaml
- insert:
    - id: aeval-broker-transport
      name: 'dsh-eval-control/dist/sandbox_entry.js'
      config:
        controlConfigPath: '/absolute/path/control-config.json'
    - id: aeval-eval-control
      name: 'dsh-eval-control/dist/index.js'
      config:
        controlConfigPath: '/absolute/path/control-config.json'
```

已有默认 transport 行时，应按行 ID 覆盖它的配置，再插入控制行。aeval runner 会为评测试次生成对应 patch 并部署控制栈。

在本包已构建的目录中执行自检：

```bash
node dist/selfcheck.js
node dist/selfcheck.js --config /absolute/path/control-config.json --json
```

本包还提供 `aeval-dsh-session-reader`、`aeval-dsh-session-stub` 和 `aeval-model-broker` 三个命令，供评测采集与控制流程使用。

| `cordis.patch.yml` | 默认组合包挂载声明 |
| `test/` | 宿主、前端、配置、报告及分享测试 |

## 常见问题

**安装后没有“轨迹分析”？**

检查 profile 是否正确、插件是否启用、peer 版本是否满足。重建前端后重新加载页面；重建宿主代码后确认服务已重新加载。

**为什么控制状态是 standalone？**

当前没有评测控制配置。这是正常的普通分析模式；需要跑受控评测时再接入完整控制栈。

**为什么“压缩次数”和“压缩频率”看起来不同？**

先核对是否包含历史修剪，以及分母是否为输入 Token。时间线区分摘要压缩与历史修剪；告警和对比的频率采用摘要压缩口径。

**为什么两条 Token 曲线不同？**

窗口占用包含缓存读，表面 Token 是消息内容估算，顶部消耗则采用未缓存输入加输出。它们回答的问题不同。

**为什么配置应用成功后，当前会话还没变化？**

检查界面中的生效范围。Agent 预设修改用于新建会话，已经运行的会话保留原预设版本。

**差异报告在哪里下载？**

在对比 Tab 完成“开始对比”，再到顶部“导出”选择团队版和 PDF、Markdown 或 HTML。

**为什么同事打不开分享链接？**

检查链接是否为本机地址、宿主是否运行、有效期及密码。团队访问需要可达的宿主地址。

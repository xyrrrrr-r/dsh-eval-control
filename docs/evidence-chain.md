# 证据链设计与实现

交互路径：**异常或指标 → 规则与输入快照 → 关联事件 → 原始轨迹行 / JSON**。

所有入口共用右侧抽屉，不切换或重建当前 Tab。打开时固定结论的数据快照；实时投影更新不会悄悄改变正在核查的结论。支持 Esc 关闭、键盘焦点约束和关闭后恢复入口焦点。

## 数据约定

`client-src/evidence.ts` 定义 `EvidenceChain`：结论、规则、证据等级、输入事实（值和来源）、事件引用、质量说明。`EvidenceRef` 使用 `sessionId + seq` 作身份，并标记引用角色。相同序号在不同会话中是不同事件。

已有指标直接复用 `MetricResult.evidenceRefs / evidenceLevel / qualityRefs / sampleCount / denominator`，不重写宿主指标算法。界面明确区分：

- `observed`：原始观测。
- `derived`：计算结果。
- `inferred`：推断。

消息突增与演化激增共用 `spikeInfo`：按原始事件序号排序，取前最多 5 条已保留消息；至少 3 个基线样本，本条至少 1,000 Token 且达到中位数 3 倍。类型筛选不会重算检测基线。主导成分比例以文本、工具调用和文件/图像成分之和为分母，与现有成分展示一致。

相邻消息体积差是两条消息的估算体积之差，不是上下文净增长。相邻消息时间差不代表生成耗时。服务商输出 usage 不由消息估算倒推。骤降只关联序号区间内的压缩事件，无法匹配时保留“推断”状态；区间净下降不等于压缩总回收量。

诊断契约的 `tool.failure_rate` 使用去重且错误标记已知的结果作分母；工具图与对比页的错误率使用调用数作分母。两者分别展示各自依据。

## 窗口占用的字段与计算映射

窗口占用使用 `contextOccupancyEvidence` 构建独立计算卡片，不沿用累计指标的泛化提示：

1. 未缓存输入绑定用量事件的 `data.usage.inputTokens`。
2. 缓存读取绑定同一用量事件的 `data.usage.cacheReadTokens`。
3. 窗口上限独立绑定配置事件的 `data.contextWindow`。
4. 展示精确数值求和，以及除以窗口上限后的百分比。

用量记录来自 `assistant/message`，含义是生成这条回复所用请求的输入占用；本条回复正文和输出 Token 不属于分子。点击字段来源后，根据精确会话、事件序号和预期事件类型核对原始字段，分别显示一致、缺失、快照不一致或类型不符。

未上报缓存读取时保留未知值，求和按现有曲线的 0 回退规则展示并说明，不能显示成已核实的 0。旧投影缺失窗口配置引用时保留已知数值并提示来源缺失，不猜测序号。无请求样本时不把表面估算冒充已验证请求用量。附近事件默认折叠，不作为额外计算样本。

## 原始记录读取

`client-src/evidencePanel.tsx` 通过已注入的 `sessions.using` 保留目标会话，等待 `ready`，调用 `binding.session.loadThrough(seq)`，再从公开 `binding.eventSource` 读取持久事件。不会将 projection 节选或 transient 流式数据当成原始证据。

精确查找目标序号，返回其前后最多 3 个事件；找不到目标时显示错误，不自动跳到最近记录。默认展示目标事件；相邻行收在“查看附近轨迹”折叠区，可选中检查 JSON，并明确与计算来源区分。展示 JSON 超过 100,000 字符时截断，单条下载保留完整内容。

读取有 15 秒超时、取消及过期结果保护。切换事件、关闭抽屉和切换会话都会取消读取，释放本次保留的会话引用。事件引用每页 20 条，可按会话、序号和角色搜索。

宿主原生 Trajectory 的 focus 目前只接受工具调用 ID。本实现保留当前会话的 `inspectCall(callId)` 原生跳转；其他事件及跨会话引用在抽屉内的原始轨迹区精确定位，不向宿主传入伪造的序号 focus。

## 投影来源补齐

`contextTimeline` 缓存版本从 5 升到 6，宿主会按版本重建投影，原始日志不变：

- 工具定义节点使用真实 `request/header` 序号，替代此前的展示占位 `0`。
- `contextWindowSeq` 记录最新窗口元数据来源。
- 压缩行的 `evidenceRefs` 保留最多 4 个生命周期来源：开始、摘要/修剪、替换、结束；快照额外提供被替换消息与替代内容引用。

旧投影或缺失来源不会被填入猜测序号。有界事件列表不是累计统计的完整计算样本。部分指标（例如内置累计模型耗时、分支首活动）缺少足够的起止引用时，会明确声明当前不能完整重算。

Team 并发扫描统一采用半开区间：同一时刻先处理结束，再处理开始，避免首尾衔接的成员被误算成并发；与宿主精确指标算法一致。
